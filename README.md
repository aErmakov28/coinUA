# CoinUA — каталог монет, наборів і банкнот

Інтернет-магазин для колекціонерів: сучасний інтерфейс (світла й темна теми, «скляні» панелі, bento-блоки, 3D-монети), детальні характеристики й зручні фільтри.

Статичний сайт на чистих HTML, CSS і JavaScript: без збірки й залежностей.

## Запуск

Відкрийте `index.html` у браузері або запустіть будь-який локальний сервер:

```bash
npx serve .
# або
python -m http.server 8000
```

## Що вміє

- **Категорії:** монети, набори, банкноти, медалі й жетони, альбоми й капсули.
- **Пошук** за назвою, кодом, роком, матеріалом (клавіша `/` ставить курсор у пошук).
- **Фільтри:** період, роки випуску, стан за шкалою Шелдона (VF … PROOF), максимальна ціна, «лише в наявності», «немає в моїй колекції», матеріал.
- **Активні фільтри** показуються тегами, кожен можна прибрати одним кліком.
- **Сортування** за новизною, ціною, роком і назвою.
- **Два вигляди:** сітка карток або таблиця.
- **Картка товару:** характеристики, наявність, кошик, обране, позначка «Є в моїй колекції».
- **Порівняння** до 4 предметів; рядки з відмінностями підсвічуються.
- **Обране** і **Моя колекція** — зберігаються в браузері (localStorage).
- **Кошик** із кількістю та підсумком і **оформлення замовлення** (доставка Новою Поштою, Укрпоштою чи самовивіз; оплата карткою, при отриманні або за рахунком).
- **Особистий кабінет** (`account.html`): реєстрація та вхід за **поштою або номером мобільного** з паролем; профіль і адреса доставки, історія замовлень з повтором, обране, моя колекція, зміна пароля, відновлення доступу.
- **Світла й темна тема** (за налаштуванням системи, перемикач у шапці; вибір запам’ятовується).
- Адаптивна верстка для телефона, навігація з клавіатури, доступні підписи.

## Структура

```
index.html        каталог
account.html      особистий кабінет
css/styles.css    стилі та адаптив
js/data.js        каталог (демо-дані)
js/config.js      налаштування (ключі Supabase)
js/auth.js        реєстрація, вхід, вікно авторизації
js/ui.js          оформлення: перемикач теми, hero-блок, нахил монети
js/account.js     сторінки кабінету
js/app.js         логіка каталогу: фільтри, кошик, порівняння, оформлення
```

## Дані

`js/data.js` містить **демонстраційні** товари: ціни, залишки й характеристики умовні.
Замініть їх реальним каталогом або підвантажуйте з API. Поля товару:

| Поле | Опис |
|---|---|
| `id`, `code` | внутрішній ідентифікатор і код за каталогом |
| `cat` | `coins`, `sets`, `banknotes`, `medals`, `accessories` |
| `metal` | `gold`, `silver`, `cuni`, `steel`, `paper`, `mixed` |
| `period` | `rus`, `unr`, `ussr`, `ua` |
| `year`, `grade`, `price`, `stock` | рік, стан, ціна в гривнях, залишок |
| `weight`, `diameter`, `edge`, `desc` | характеристики та опис |
| `image` | (необов’язково) шлях до фото; без нього малюється умовне зображення |

## Особистий кабінет

Кабінет працює у двох режимах — перемикається у `js/config.js`.

### Демо-режим (за замовчуванням)

Ключі в `config.js` порожні → акаунти зберігаються в `localStorage` цього браузера,
пароль — як хеш PBKDF2-SHA256 із сіллю. Зручно, щоб показати інтерфейс,
але **не підходить для реальних клієнтів**: акаунт не переноситься на інший пристрій,
листів і SMS немає.

### Справжня реєстрація через Supabase

1. Створіть безкоштовний проєкт на [supabase.com](https://supabase.com).
2. **Settings → API**: скопіюйте *Project URL* і *anon public key* у `js/config.js`.
3. **Authentication → URL Configuration**:
   - *Site URL*: `https://aermakov28.github.io/coinUA/`
   - *Redirect URLs*: `https://aermakov28.github.io/coinUA/account.html`
4. **Authentication → Providers → Email** — увімкнено за замовчуванням (лист із підтвердженням).
5. **Authentication → Providers → Phone** — увімкніть і підключіть SMS-провайдера
   (Twilio, MessageBird, Vonage або Textlocal; SMS платні). Без цього реєструватися
   можна лише поштою.
6. Закомітьте `config.js` — сайт сам перейде в справжній режим.

Що тоді працює: підтвердження пошти листом, телефону — 6-значним SMS-кодом,
відновлення пароля листом або SMS, сесія й дані акаунта на всіх пристроях.

Профіль, обране, колекція й замовлення зберігаються в `user_metadata` користувача.
Для справжнього магазину замовлення варто перенести в окрему таблицю з
Row Level Security (користувач не повинен сам змінювати статус замовлення).
